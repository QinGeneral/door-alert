# 门前 AM312 与三色灯联调

接线：AM312 VCC→3V3、OUT→D2/GPIO4、GND→GND；
共阴灯 R→D6/GPIO21、Y→D7/GPIO20、G→D10/GPIO10、GND→GND。
模块与开发板共地，USB供电。灯模块须有自带限流电阻。

上电先黄灯每0.5秒闪烁，预留30秒稳定时间；之后AM312触发时红灯，
未触发时绿灯。输入经100ms滤波，输出变低后红灯额外保持2秒。
AM312本身的输出延时还会增加实际熄灯等待时间。

这是门前传感器联调程序。红灯只说明门前检测到活动，绿灯只说明门前
PIR当前未触发；均不表示门后状态。静止人体、断开的传感器不能由本程序排除。
尚未加入ESP-NOW、门后测距或电池休眠功能。

串口115200，每秒及状态变化时输出一行JSON，包含raw/stable及三色灯输出。
`WARMUP`=预热，`MOTION`=触发/保持，`IDLE`=未触发。

现场测试：上电等30秒后，在探头前走动或挥手，观察红灯；离开视野，
等待模块输出及软件保持时间结束，观察绿灯。此前的独立灯循环程序保留在
相邻目录 `../traffic-light`。

## v2 输入修正

针对v1始终读到低电平的现象，将GPIO4从INPUT_PULLDOWN改为高阻INPUT，
避免内部下拉给AM312输出增加负载。该变更是排查措施，尚不能单独证明
问题源于下拉。OUT必须可靠连接；悬空输入的读值没有探测意义。
v1记录保留，v2诊断记录单独保存。

v2已编译、烧录并通过写入哈希校验。45秒采样期间，在预热14.506秒时
读到高电平，17.361秒恢复低电平；30秒后进入IDLE。说明该次采样观察到
GPIO4输入变化，但高电平发生在预热期，尚未验证预热后MOTION红灯路径。
后续30秒串口采样再次从ms=0开始，至30秒进入IDLE；可能存在打开串口
导致重启的行为，后续若需联调应持续保持同一次串口会话，避免重复预热。
v2记录：`verification/v2-serial.jsonl`、`v2-result.json`及`v2-followup.jsonl`。
